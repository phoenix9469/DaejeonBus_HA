# 대전 버스 (Daejeon Bus) for Home Assistant

대전광역시 버스정보(BIS) 공공데이터 API를 쓰는 Home Assistant 커스텀 통합구성요소입니다.
[miumida/seoul_bus](https://github.com/miumida/seoul_bus)를 참고해 만들었습니다.

항목 유형은 두 가지입니다.

| 유형 | 용도 | 입력 | 출력 |
| --- | --- | --- | --- |
| **정류소 도착정보** | 정류소에 오는 모든 버스 보기 | 정류소 번호 `arsId` | 노선별 잔여 정류장 수, 최근 통과 정류소, 도착예정시간 |
| **출근 알리미** | 언제 집을 나서면 되는지 보기 | 내 정류장 `arsId` + 노선 | 노선의 모든 버스가 내 정류장까지 몇 정류장/몇 분 전인지, 출발까지 남은 시간 |

- 기본은 **자동 갱신 없음**입니다. 통합구성요소를 로드할 때 1회 조회하고, 이후에는 `새로고침` 버튼을 누를 때만 조회합니다.
- 자동 조회는 [옵션](#자동-조회-옵션-기본-꺼짐)에서 요일·시간대를 정해 켤 수 있습니다.

## 설치

### HACS
1. HACS → 사용자 지정 저장소 → `https://github.com/phoenix9469/DaejeonBus_HA` (유형: Integration)
2. `대전 버스` 설치 후 Home Assistant 재시작

### 수동
`custom_components/daejeon_bus` 폴더를 Home Assistant 설정 폴더의 `custom_components/` 아래에 복사한 뒤 재시작합니다.

## 설정
설정 → 기기 및 서비스 → 통합구성요소 추가 → **대전 버스** → 항목 유형 선택

### 정류소 도착정보

| 항목 | 설명 |
| --- | --- |
| API 키 | [공공데이터포털](https://www.data.go.kr) 대전광역시 버스도착정보 서비스키 (인코딩/디코딩 키 모두 가능) |
| 정류소 번호 (arsId) | 예: `31770` |
| 정류소 이름 (선택) | 비워두면 API의 정류소 이름(`STOP_NAME`) 사용 |
| 대상 버스 목록 (선택) | 쉼표로 구분한 노선번호, 예: `3,103,119`. 비워두면 전체 노선 |

정류소 하나당 항목 하나를 추가합니다. API 키·이름·대상 버스·'곧 도착' 기준·자동 조회는 나중에 `구성`에서 바꿀 수 있습니다.

## 정류소 도착정보 엔티티 (arsId `31770` 예시)

| 엔티티 | 상태 | 주요 속성 |
| --- | --- | --- |
| `button.daejeon_bus_31770_refresh` | 새로고침 버튼 | – |
| `sensor.daejeon_bus_31770` | 도착예정 버스 수 (운행대기 제외) | `버스 목록` (노선별 첫 차 요약) |
| `sensor.daejeon_bus_31770_3` (노선별) | `5분 7초 (4정류장 전)` / `곧 도착 (1정류장 전)` / `도착` / `진입중` / `운행대기` | `운행 상태`, `메시지 유형`, `첫/막차`, `노선유형`, `잔여 정류장 수`, `최근 통과 정류소`, `최근 통과 정류소 ID`, `도착예정시간`, `도착예정(분)`, `도착예정(초)`, `행선지`, `차량번호`, `정보 제공 시각`, `다음 버스` |
| `sensor.daejeon_bus_31770_last_update` | 마지막 조회 시각 | – |

- 노선 센서는 도착정보에 나타난 노선마다 생성되며, 새로고침 후 새 노선이 보이면 자동으로 추가됩니다.
- 해당 노선의 도착정보가 없으면 상태는 `도착정보 없음`입니다.
- 노선 센서의 상태는 아래 순서로 정해집니다.
  1. `MSG_TP` `01` → **도착**
  2. `06` → **진입중**
  3. `07` → **운행대기** (차고지 대기, 도착시간·위치 값 없음)
  4. 도착예정시간이 기준 이하 → **곧 도착 (N정류장 전)** (기본 3분, `구성`에서 `'곧 도착' 기준 (분)`으로 변경, 0이면 끔)
  5. 그 외 → **도착예정시간 (N정류장 전)**, 예: `5분 7초 (4정류장 전)`
- 상태가 `곧 도착`이어도 실제 남은 시간은 `도착예정시간` 속성에 남아 있습니다. 운행대기 버스는 목록 맨 뒤로 정렬됩니다.

## 도착정보 항목 (getArrInfoByUid)

대전 BIS「OpenAPI 활용가이드 v1.3」 기준입니다.

| 항목 | 뜻 | 값 / 비고 | 센서 속성 |
| --- | --- | --- | --- |
| `BUS_NODE_ID` | 요청 정류소 ID (7자리) | 예: `8001056` | – |
| `BUS_STOP_ID` | 요청 정류소 ARS-ID | 대전 5자리, 광역 6자리 | `정류소 ID(arsId)` |
| `STOP_NAME` | 요청 정류소 명칭 | | `정류소 이름` |
| `ROUTE_CD` | 노선 ID (8자리) | | `노선 ID` |
| `ROUTE_NO` | 노선번호 | | `노선번호` |
| `ROUTE_TP` | 노선유형 | 1 급행 · 2 간선 · 3 지선 · 4 외곽 · 5 마을 · 6 첨단 | `노선유형` |
| `DESTINATION` | 종점 | | `행선지` |
| `CAR_REG_NO` | 차량번호 | | `차량번호` |
| `EXTIME_MIN` | 도착예정시간(분) | 올림한 분 | `도착예정(분)` |
| `EXTIME_SEC` | 도착예정시간(초) | 남은 전체 초 (예: 317초 = 5분 17초, MIN=6) | `도착예정(초)`, `도착예정시간`, 상태값 |
| `STATUS_POS` | 잔여 정류장 수 | | `잔여 정류장 수` |
| `LAST_STOP_ID` | 최근 통과 정류소 ID (5자리 arsId) | 이름으로 변환 | `최근 통과 정류소`, `최근 통과 정류소 ID` |
| `MSG_TP` | 메시지유형 | 01 도착 · 02 출발 · 03 몇분후 도착 · 04 교차로 통과 · 06 진입중 · 07 차고지 운행대기중 | `메시지 유형`, `운행 상태` |
| `LAST_CAT` | 첫/막차 구분 | 1 첫차 · 2 막차 · 3 일반 (운행대기 차량은 0으로 오기도 함) | `첫/막차` |
| `INFO_OFFER_TM` | 정보 생성 시간 | | `정보 제공 시각` |

## 정류소 이름 (최근 통과 정류소)

도착정보 API는 최근 통과 정류소를 번호(`LAST_STOP_ID`)로만 줍니다. 이름은 이렇게 찾습니다.

1. **캐시 파일**: `/config/.storage/daejeon_bus_stop_names`
   - arsId와 이름을 JSON으로 저장해 둔 파일입니다.
   - 모든 항목이 같이 씁니다.
2. 파일에 없으면 **정류소정보 API**로 조회합니다.
   - 호출: `https://apis.data.go.kr/6300000/stationinfo/getStationByUid?arsId=...` → `BUSSTOP_NM`
   - 이 주소가 실패하면 대전시 BIS 원본 서버(`openapitraffic.daejeon.go.kr`)를 시도합니다.
   - 찾은 이름은 파일에 추가되므로, 같은 정류소는 다시 조회하지 않습니다.
3. **출근 알리미**를 쓰면 노선 경유 정류소 목록(정류장 이름 포함)을 받을 때 그 이름들도 같은 파일에 들어갑니다.

- **API 조회가 실패할 때:** 모든 조회가 실패하면 HA를 재시작할 때까지 API 조회를 멈추고, 정류소 번호를 그대로 보여줍니다. 서비스키 권한 문제일 수 있으니 공공데이터포털에서 정류소정보 조회 서비스 활용신청 여부를 확인하세요.
- **이름 고치기·새로 받기:** 캐시 파일을 직접 고칠 수 있습니다. 파일을 지우면 다음 조회 때 다시 받습니다. 고칠 때는 HA를 중지하고 수정하세요. 실행 중에 고치면 덮어써질 수 있습니다.

## 출근 알리미

특정 노선이 **내 정류장까지 몇 정류장 전인지**, **언제 나가면 되는지** 보여줍니다.

### 설정 순서
1. **내 정류장**: API 키, 정류장 번호(arsId)
2. **노선**: 그 정류장 도착정보에 나오는 노선 중 선택
   - 목록에 없으면(심야 등) 노선번호나 노선 ID(8자리, 예: `30300146`)를 직접 입력합니다.
3. **방향**: 노선이 그 정류장을 두 번 지날 때만 고릅니다. 다음 정류장 이름으로 구분합니다.
4. **도보 시간(분)**, **출발 알림 여유(분)**

### 계산 방법

쓰는 API는 세 가지입니다.

| API | 용도 | 호출 |
| --- | --- | --- |
| `busRouteInfo/getStaionByRoute` | 노선 정류장 순번·누적거리 | 하루 1번 (캐시) |
| `busposinfo/getBusPosByRtid` | 노선의 모든 버스 위치 | 조회할 때마다 |
| `arrive/getArrInfoByUid` | 내 정류장 도착예정시간 (보정용) | 조회할 때마다 |

- **위치 판정**
  - 버스의 기점부터 누적거리(`TOTAL_DIST`)가 내 정류장 누적거리보다 작으면, 아직 오지 않은 버스입니다.
  - 버스 위치의 정류장 순번과 내 정류장 순번의 차이가 **남은 정류장 수**입니다.
  - 누적거리는 왕복 전체 기준이라 상행·하행이 자연스럽게 구분됩니다.
- **도착예정시간**
  - 도착정보 API에 같은 차량번호가 있으면 그 값을 씁니다.
  - 없으면 실제 값이 있는 버스로 보정한 속도(m/분)로 추정합니다. 이때는 `추정값: true`로 표시됩니다.
  - 보정할 버스가 없으면 기본 속도 250m/분으로 추정합니다.
- **출발까지** = 탈 수 있는 첫 버스의 도착예정 − 도보 시간
  - 도착예정이 도보 시간보다 짧은 버스는 놓친 것으로 보고, 다음 버스를 기준으로 합니다.

### 엔티티 (213번, 갈마네거리 31770 예시)

| 엔티티 | 상태 | 비고 |
| --- | --- | --- |
| `sensor.daejeon_bus_commute_213_31770` | `지금 출발` / `2분 30초 후 출발` / `탈 수 있는 버스 없음` | 속성 `버스 목록`: 접근 중인 버스 전체 |
| `sensor.daejeon_bus_commute_213_31770_first_stops` | `3` (정류장) | 첫 번째 버스 남은 정류장 |
| `sensor.daejeon_bus_commute_213_31770_first_minutes` | `5.0` (분) | 첫 번째 버스 도착예정 |
| `sensor.daejeon_bus_commute_213_31770_second_stops` / `_second_minutes` | `9` / `17.4` | 두 번째 버스 |
| `sensor.daejeon_bus_commute_213_31770_leave_in` | `1.0` (분) | 출발까지 남은 시간 |
| `binary_sensor.daejeon_bus_commute_213_31770_leave_now` | on/off | 출발까지 ≤ 출발 알림 여유이면 on |
| `button.daejeon_bus_commute_213_31770_refresh` | | 새로고침 |
| `sensor.daejeon_bus_commute_213_31770_last_update` | 시각 | 마지막 조회 |

버스별 속성에는 `차량번호`, `남은 정류장`, `남은 거리(m)`, `도착예정(분)`, `추정값`, `현재 정류장`이 있습니다.

### 자동화 예시: 나갈 시간이면 알림
```yaml
triggers:
  - trigger: state
    entity_id: binary_sensor.daejeon_bus_commute_213_31770_leave_now
    to: "on"
actions:
  - action: notify.mobile_app_내폰
    data:
      message: >
        213번 {{ states('sensor.daejeon_bus_commute_213_31770_first_stops') }}정류장 전,
        지금 나가세요
```

## 자동 조회 옵션 (기본 꺼짐)

두 항목 유형 모두 `구성`에서 켤 수 있습니다.

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| 자동 조회 사용 | 꺼짐 | 끄면 새로고침 버튼으로만 조회 |
| 시작 / 종료 시각 | 07:00 / 09:00 | 같으면 하루 종일, 자정을 넘는 구간 가능 |
| 요일 | 월~금 | |
| 간격 | 60초 | 최소 30초 |

공공데이터포털 개발 키는 하루 호출 수 제한(보통 1,000회)이 있습니다. 출근 알리미는 1회 조회에 API 2번을 쓰므로 60초 간격·2시간이면 약 240회입니다.

## 대시보드 예시

```yaml
type: vertical-stack
cards:
  - type: button
    entity: button.daejeon_bus_31770_refresh
    name: 새로고침
    tap_action:
      action: perform-action
      perform_action: button.press
      target:
        entity_id: button.daejeon_bus_31770_refresh
  - type: markdown
    content: >
      {% set s = 'sensor.daejeon_bus_31770' %}
      **{{ state_attr(s, '정류소 이름') }}** ({{ state_attr(s, '정류소 ID(arsId)') }})
      · 조회 {{ as_timestamp(states('sensor.daejeon_bus_31770_last_update')) | timestamp_custom('%H:%M:%S') }}

      | 노선 | 도착예정 | 최근 통과 | 행선지 |
      |---|---|---|---|
      {% for b in state_attr(s, '버스 목록') or [] -%}
      | {{ b['노선'] }} | {{ b['도착예정'] }} | {{ b['최근 통과 정류소'] }} | {{ b['행선지'] }} |
      {% endfor %}
```

자동화에서 조회하려면 `button.press` 서비스로 새로고침 버튼을 누르면 됩니다.

> 참고: API의 `EXTIME_SEC`는 전체 남은 초, `EXTIME_MIN`은 올림한 분입니다. 상태값(`5분 7초` 등)은 `EXTIME_SEC` 기준입니다.
